01 — Goal

A level gets real internal structure

A sequence of discrete rooms you fight through and clear, gated by checkpoints — instead of one continuous generated space. Modeled on Dead Cells / Castlevania / Hollow Knight room pacing, but grafted onto CINDER LOOP's own locked identity rather than replacing it.

02 — The One Decision Everything Depends On

Death still ends the run

D1, this project's very first locked decision, defines the run loop as spawn → clear → boss → die → spend → respawn, with death as one of exactly two ways a run ends. This feature does not change that.

Rooms & checkpoints are pacing, not death-recovery

A death anywhere, in any room, still ends the whole run exactly as it does today. There is no “resume at your last checkpoint after dying” the way a bonfire or save crystal would work. That model was considered and explicitly rejected in favor of keeping D1 intact.

03 — Room Graph & Pacing

A linear chain: three rooms, then the boss

Difficulty escalates room 1 → 2 → 3 via enemy count/composition — the same lever D2's stat scaling already uses elsewhere. The boss room is the existing boss encounter, now framed as the final room in the chain.

04 — Generation

Reusing what already exists

Reuses proven, shipped machinery

The biggest risk-reducer in this whole design: the mechanism this needs already exists. Sim._enterLevel() / Sim._enterBoss() already tear down one World and load a fresh one mid-run for the level→boss transition. Room-to-room reuses that exact shape, called in a loop instead of once. Each combat room is one Gen.generate() call bounded to smaller dimensions, independently fairness-audited by the same D3a machinery.

05 — Room Content

Procedural rooms, two hand-shaped exceptions

Combat rooms (×3)

Fully procedural, per §04. Zero new hand-authored content — needs infinite variety, so it stays generated.

Checkpoint & boss rooms

A small number of hand-authored layouts each. A narrow, deliberate exception to “procedural over hand-authored” — bounded to these two room types, meant to feel designed rather than generated.

06 — What “Clear” Means

Reused from D1, scoped to a room

Every enemy this room placed has hp ≤ 0, and a living player has reached the room's own exit. Reaching the door alone doesn't clear it; killing everything without reaching the door doesn't either. The door to the next room stays locked until both are true.

08 — Cinders

A resource that is genuinely at risk

Distinct from currency, which stays exactly as safe as it already is — see §09. Named for the game's own kiln / ash / ember vocabulary.

Banking is deliberate, not automatic. The checkpoint room holds a real interactable object — the pneumatic tube. Reaching it does not auto-bank cinders; the player walks up and interacts. That turns the checkpoint into a real decision: bank now for safety, or keep carrying into the next room for fewer trips, at the real risk of losing everything to one death. No multiplier for waiting — the risk itself is the whole mechanic.

09 — What Does Not Change

The existing guarantees hold

Untouched by this feature

Currency still converts to permanent progress at run-end on either death or victory — cinders are a new, riskier income stream INTO that pool, not a change to the rule. Death still ends the whole run. The permanent meta-progression store (currency, unlocked blueprints) is untouched — the new save-and-quit key is a separate, run-scoped payload.
